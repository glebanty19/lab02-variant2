# Лабораторна робота № 2 — варіант 2

## Стан роботи

Варіант: класифікація стану будівель після руйнувань за чотирма класами на фрагментах xBD.

Набір із 96 фрагментів сформовано з архіву `train_images_labels_targets.tar`. Джерельні мітки xBD, розбиття, контрольні суми й автоматичні перевірки підготовлені. Підсумки перевірки узгодженості та її обмеження наведені у звіті.

Публічний репозиторій проєкту: https://github.com/glebanty19/lab02-variant2. Через непідтверджені умови повторного поширення xBD він містить маніфест, джерельну розмітку, код і звіт, але не архів і не похідні зображення. Анотаційні CSV посилаються на локальну папку `annotation_images/`, якої немає в репозиторії. Потрібні фрагменти можна відтворити з дозволеного архіву xBD командою `python prepare_xbd.py train_images_labels_targets.tar`.

## Файли

- `manifest.csv` — маніфест зразків; один рядок на фрагмент із цільовою будівлею.
- `guideline_v1.md` / `guideline_v2.md` — початкова й уточнена інструкції з анотації.
- `annotation-results/` — форми, повторні оцінки, розбіжності, невпевнені випадки та підсумок каппи.
- `prepare_xbd.py` — потоково відбирає невеликий набір із Challenge-архіву без повного розпакування.
- `dataset_tools.py` — перевірки маніфесту, розбиття за сценами, статистика, дублі й каппа.
- `report.md` / `report_variant2.docx` — звіт із фактичними результатами та відкрито зазначеними невиконаними ручними перевірками.
- `report_template.md` — початковий шаблон.

## Підготовка даних

1. Отримайте доступ до дозволеного набору xBD/xView2 або Maxar Open Data та зафіксуйте точну версію, походження і ліцензійні умови. Не поширюйте зображення, якщо ліцензія цього не дозволяє.
2. Відіберіть 80–200 фрагментів із щонайменше чотирьох незалежних сцен. Для перевірки узагальнення бажано мати більше сцен; усі зразки однієї сцени/локації мають лишатися в одній підмножині.
3. Кожен фрагмент має містити одну цільову будівлю, яку можна зіставити з первинною розміткою. Запишіть її клас за офіційною легендою джерела. Не виводьте клас після руйнування з ознак до події.
4. Двоє учасників незалежно розмічають щонайменше 30 однакових зразків. Після обговорення розбіжностей уточніть інструкцію і повторно розмітьте 10 зразків.
5. Для архіву `train_images_labels_targets.tar` скрипт `prepare_xbd.py` створює 96 RGB-фрагментів 256×256 px з офіційними післяподієвими класами для чотирьох подій. Оригінальні PNG/JSON не розпаковуються. Один disaster event використовується як група: Harvey і Matthew — train, Michael — val, Florence — test. Це дає нуль спільних подій між підмножинами, але розподіл 50/25/25 є навмисно відмінним від типової частки зразків 70/15/15.
6. Джерельні мітки xBD не є незалежною подвійною студентською анотацією. Для обов'язкової перевірки двома людьми використайте сліпу чергу з 32 зразків `labels/double_annotation_queue.csv`; не показуйте `labels/source_annotation_key.csv` до фіксації обох форм. Наявні результати в `annotation-results/` є попередньою перевіркою узгодженості, а не заміною людського етапу. Перед здачею двоє учасників мають незалежно заповнити окремі форми, обговорити розбіжності й виконати повторний раунд за уточненою інструкцією; після цього проведіть арбітраж і зафіксуйте людські результати.
   Розпакуйте локальний `annotation_packet.zip`; кожному учаснику передайте лише його CSV та спільну папку `images/`. Не передавайте `source_annotation_key.csv`, маніфест чи інші файли з мітками. Після завершення покладіть обидва заповнені CSV з назвами `annotator_1.csv` і `annotator_2.csv` в одну локальну теку, наприклад `annotation-results/`. Бірюзовий контур у фрагментах показує цільову будівлю.
7. Після заповнення незалежних міток у CSV запустіть:

   ```text
   python dataset_tools.py manifest.csv --output-dir stats --annotations PATH_TO_COMPLETED_ANNOTATOR_FOLDER
   ```

Скрипт перевіряє структуру, обчислює фактичну каппу для парних міток, зберігає задане групове розбиття та статистику, шукає точні/перцептивні дублікати та повторне використання одного вихідного зображення у різних підмножинах. `--annotations` приймає теку з повернутими `annotator_1.csv` і `annotator_2.csv` з пакета або зведений CSV. Перетини піксельних фрагментів перевіряються лише для фрагментів того самого вихідного зображення. Архів PNG не містить геоприв'язки, тому глобальну географічну суміжність і збіг локацій між різними знімками перевірити неможливо без геотрансформацій. Перцептивний хеш також не є доказом відсутності всіх майже-дублікатів.

## Структура для подальшого зберігання даних

```text
lab02_variant2/
├── README.md
├── report.md / report_variant2.docx
├── guideline_v1.md
├── prepare_xbd.py / dataset_tools.py
├── manifest.csv / split.csv
├── images/                            # 96 похідних фрагментів
├── annotation_images/                 # копії 32 анонімізованих фрагментів для сліпої розмітки
├── labels/
│   ├── source_annotations.csv
│   ├── source_annotation_key.csv      # для арбітражу; не показувати анотаторам
│   └── double_annotation_queue.csv    # 32 зразки, 10 для повторного раунду
└── stats/                             # статистика, перевірки, графіки, контрольні суми
```

Сирий архів `train_images_labels_targets.tar` навмисно не входить до Git: його розмір близько 8,4 ГБ. Публічний GitHub-репозиторій також не містить `images/`; маніфест і джерельна розмітка дають змогу перевірити структуру набору та відтворити похідні фрагменти локально.
